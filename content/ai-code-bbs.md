## 缘起

本机有一个跑了十年的 ASP.NET Core 论坛，代码量不大，但历史包袱不少。我想试试：能不能让本地模型直接参与改码，而不是只在聊天窗口里给建议。

最后的做法不是“把仓库丢给 AI”，而是把能力拆成五个受控工具：

| 工具 | 作用 | 权限 |
| --- | --- | --- |
| `code_search` | 按正则检索 | `code.read` |
| `code_read` | 读文件片段 | `code.read` |
| `code_write` | 新建文件 | `code.write` |
| `code_patch` | 按原文替换 | `code.write` |
| `code_build` | 编译指定项目 | `code.write` |

## 坑一：模型给的不是补丁，是“看起来像补丁”的文本

最早我让模型输出 JSON：`{oldText, newText, explanation}`。本地 27B 模型经常在 `explanation` 里换行、不转义，JSON 直接解析失败；上下文一长，输出还会被截断。

后来改成更笨但更稳的办法——用分隔符：

```
<<<OLD
原样复制的旧代码
>>>OLD
<<<NEW
替换后的新代码
>>>NEW
<<<WHY
一句话说明
>>>WHY
```

模型不需要处理转义，解析只需要找标记。补丁应用前再校验一次：`oldText` 在文件里必须恰好出现一次，否则拒绝。这一步比任何提示词都管用。

## 坑二：备份目录会污染仓库

`code_patch` 每次改前都备份，一开始备份就放在源码树里的 `.tenantai-backups`。结果一打开 VS Code 的源代码管理，满屏都是“新增文件”，根本看不出哪些是真正的改动。

修法很简单：把备份根目录做成配置项，默认放在源码树之外，例如：

```json
"Code": {
  "Root": "E:\\bbs2",
  "BackupRoot": "E:\\AI\\TenantAI\\code-backups\\bbs2"
}
```

备份该留，但不该出现在版本控制的视野里。

## 坑三：没有编译反馈，AI 改码等于赌博

只让模型改文本是不够的。每次应用补丁后必须能编译，否则语法错误会一路带到运行期。

`code_build` 负责这件事：固定工作目录、强制 UTF-8 输出、把 CLI 语言设为英文，避免中文乱码污染判断。返回结构只有四个字段：

```json
{ "exitCode": 0, "success": true, "elapsedMs": 2141, "tail": ["Build succeeded."] }
```

`exitCode` 不为 0 就把 `tail` 原样贴回给模型，让它基于真实报错重试。闭环一旦成立，人才敢真的按“应用”按钮。

## 现在的流程

搜索定位 → 预览上下文 → 中文描述改动 → 模型出补丁 → 人工核对 oldText/newText → 应用（自动备份）→ 编译校验。全程有权限校验和审计，viewer 角色连补丁都提交不了。

AI 没有变聪明，是流程把它能出错的空格一个个堵住了。
